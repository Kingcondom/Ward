# 🛏️ Ward — ระบบเก็บข้อมูลผู้ป่วยในหอผู้ป่วย (real-time)

เว็บแอปสำหรับทีมแพทย์/พยาบาลในหอผู้ป่วย: dashboard แสดงเตียง–ชื่อย่อ–Diagnosis–การรักษา
และบันทึก **SOAP รายวัน** ของผู้ป่วยแต่ละราย ข้อมูลอัปเดต **real-time** ทุกเครื่องพร้อมกัน

## คุณสมบัติ

- **Dashboard เตียง** — การ์ดต่อเตียง แสดงเตียง / ชื่อย่อ / อายุ-เพศ / Diagnosis / การรักษา
  พร้อมป้ายเตือน “ยังไม่มี SOAP วันนี้”, “✓ SOAP วันนี้” และการแพ้ยา
- **Real-time** — เพิ่ม/แก้ไขจากเครื่องหนึ่ง เครื่องอื่นเห็นทันทีโดยไม่ต้อง refresh
  (Server-Sent Events) พร้อม toast บอกว่าใครแก้อะไร และตัวนับจำนวนเครื่องที่ออนไลน์
- **SOAP รายวัน** — บันทึกได้หลายรอบต่อวัน (เช้า/เย็น) แก้ไข/ลบได้ จัดกลุ่มตามวันที่ บันทึกชื่อผู้บันทึกอัตโนมัติ
- **Round วันนี้** — รวม SOAP ของทุกเตียงในวันที่เลือก ไว้ใช้ตอน round / ส่งเวร
- **ค้นหาและกรอง** — ค้นจากเตียง / ชื่อย่อ / Diagnosis, กรองเฉพาะรายที่ยังไม่มี SOAP วันนี้,
  แสดง/ซ่อนผู้ป่วยที่ D/C แล้ว
- **V/S และ Lab พร้อมกราฟแนวโน้ม** — บันทึก BT/BP/PR/RR/O2sat และค่า Lab รายวัน
  แสดงเป็นกราฟเล็กแยกค่าละกราฟ (ไม่ใช้กราฟสองแกนที่อ่านผิดง่าย) พร้อมแถบช่วงอ้างอิง
  ไฮไลต์ค่าที่ผิดปกติด้วยสี **และข้อความกำกับ (▲ สูง / ▼ ต่ำ)** และมีตารางค่าให้ดูควบคู่เสมอ
- **Timeline การดำเนินโรค** — รวม Admit, Diagnosis, หัตถการ, Consult, ภาวะแทรกซ้อน, ย้ายหอ,
  D/C และ SOAP ทั้งหมดเป็นเส้นเวลาเดียว เหตุการณ์สำคัญบางอย่างระบบบันทึกให้อัตโนมัติ
- **นำเข้าจากข้อความโรงพยาบาล** — วางข้อความจากใบ lab / progress note แล้วระบบดึงเฉพาะ
  **ตัวเลข V/S และ Lab** ออกมาให้ตรวจก่อนบันทึก อ่านรูปแบบที่ใช้จริงได้ เช่น `AST(SGOT) 30`,
  `Sodium (Na) 140`, `Temp. 38 C`, `WBC 16.65` (หน่วยพัน), วันที่ พ.ศ. ย่อ `6/9/69`
  และค่าชุดแนวโน้ม `AST 131 > 154 > 164 > 84` (ใช้ค่าล่าสุด)
- **D/C และรับกลับเข้ารักษา** — เก็บประวัติไว้ ไม่ต้องลบทิ้ง
- รองรับมือถือ/แท็บเล็ต และ dark mode อัตโนมัติ

## เริ่มใช้งาน

ต้องมี **Node.js 22.5 ขึ้นไป** (ใช้ `node:sqlite` ที่ติดมากับ Node) — **ไม่ต้อง `npm install`** เพราะไม่มี dependency ภายนอก

```bash
WARD_PASSCODE='ตั้งรหัสผ่านของหอผู้ป่วย' npm start
# เปิด http://localhost:3000
```

เข้าใช้งานด้วย “ชื่อผู้บันทึก” (ใช้ติดชื่อในบันทึก SOAP) + รหัสผ่านของหอผู้ป่วย

### ข้อมูลตัวอย่างสำหรับทดลองใช้

```bash
npm run seed          # ใส่ผู้ป่วยสมมติ 7 ราย พร้อม SOAP, V/S, Lab และ Timeline
npm run seed:reset    # ล้างข้อมูลทั้งหมดแล้วใส่ใหม่
```

ทุกรายเป็น **เคสสมมติ** ชื่อย่อไม่ใช่ของจริง

### การอัปเกรดเวอร์ชัน

ฐานข้อมูลมีระบบ migration อัตโนมัติ (`PRAGMA user_version`) — อัปเกรดแค่ `git pull` แล้ว restart
ตารางใหม่จะถูกสร้างให้เอง **ไม่ต้องตั้งค่าใหม่ และข้อมูลเดิมไม่หาย**

> ⚠️ ข้อยกเว้นของเวอร์ชันนี้: migration 3 **ลบคอลัมน์ HN ทิ้งถาวร** เพื่อลดข้อมูลระบุตัวตน
> ถ้าฐานข้อมูลเดิมเคยเก็บ HN ไว้และยังอยากเก็บ ให้สำรอง `data/ward.db` ก่อนอัปเกรด

### ตัวแปรแวดล้อม

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | `3000` | พอร์ตที่เปิดให้บริการ |
| `WARD_PASSCODE` | `ward1234` | รหัสผ่านร่วมของหอผู้ป่วย — **ต้องตั้งเองก่อนใช้งานจริง** |
| `WARD_DB` | `./data/ward.db` | ตำแหน่งไฟล์ฐานข้อมูล SQLite |

## โครงสร้าง

```
server.js        HTTP + REST API + SSE (real-time) + session
db.js            สคีมาและ query ของ SQLite (patients, soap_notes)
public/          หน้าเว็บ (index.html, app.js, style.css) — vanilla JS ไม่มี build step
data/ward.db     ฐานข้อมูล (ไม่ถูก commit)
```

## API

ทุก endpoint (ยกเว้น `/api/login`) ต้องมี session cookie

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| POST | `/api/login` · `/api/logout` · GET `/api/me` | เข้า/ออกระบบ |
| GET | `/api/stream` | สตรีม real-time (SSE) |
| GET/POST | `/api/patients` | รายชื่อผู้ป่วย (`?all=1` รวม D/C) / รับผู้ป่วยใหม่ |
| GET/PATCH/DELETE | `/api/patients/:id` | ดู (พร้อม SOAP ทั้งหมด) / แก้ไข / ลบ |
| POST | `/api/patients/:id/discharge` · `/readmit` | D/C · รับกลับเข้ารักษา |
| GET/POST | `/api/patients/:id/notes` | SOAP ของผู้ป่วยรายนั้น |
| PATCH/DELETE | `/api/notes/:id` | แก้ไข / ลบบันทึก SOAP |
| GET | `/api/rounds?date=YYYY-MM-DD` | SOAP ของทุกเตียงในวันที่ระบุ |
| GET/POST | `/api/patients/:id/vitals` · DELETE `/api/vitals/:id` | V/S |
| GET/POST | `/api/patients/:id/labs` · DELETE `/api/labs/:id` | ผล Lab |
| GET | `/api/patients/:id/timeline` | Timeline (เหตุการณ์ + SOAP รวมกัน) |
| POST | `/api/patients/:id/events` · DELETE `/api/events/:id` | เหตุการณ์ใน Timeline |
| GET | `/api/ranges` | ค่าอ้างอิงที่ใช้ไฮไลต์ค่าผิดปกติ |
| POST | `/api/parse` | อ่านข้อความโรงพยาบาล → ข้อมูลให้ตรวจ (ยังไม่บันทึก) |
| POST | `/api/patients/:id/import` | บันทึกรายการที่ผู้ใช้ยืนยันแล้ว |

## ⚠️ ก่อนใช้กับข้อมูลผู้ป่วยจริง

ระบบนี้ออกแบบให้ใช้ใน **เครือข่ายภายในโรงพยาบาล** และมีความปลอดภัยระดับพื้นฐานเท่านั้น
(รหัสผ่านร่วมของหอผู้ป่วย, session ในหน่วยความจำ อายุ 12 ชม.) ก่อนเก็บข้อมูลผู้ป่วยจริงควรเพิ่ม

1. **HTTPS** (reverse proxy เช่น nginx/Caddy) — ตอนนี้รหัสผ่านและข้อมูลวิ่งแบบ plain HTTP
2. **บัญชีผู้ใช้รายบุคคล** แทนรหัสผ่านร่วม พร้อม audit log ว่าใครดู/แก้อะไรเมื่อไร
3. **สำรองข้อมูลและเข้ารหัสดิสก์** ที่เก็บไฟล์ `data/ward.db`
4. ตรวจสอบให้สอดคล้องกับ **PDPA** และนโยบายเวชระเบียนของโรงพยาบาล

ระบบ **ไม่เก็บ HN และไม่เก็บชื่อ-สกุล** เก็บแค่ชื่อย่อ เตียง อายุ เพศ และประวัติการรักษา
ซึ่งช่วยลดความเสี่ยงได้มาก แต่ยัง **ไม่ถือว่าเป็นข้อมูลนิรนาม** — อายุ เพศ วันที่ admit เตียง
และประวัติโรคที่ละเอียด เมื่อประกอบกันยังชี้ตัวผู้ป่วยได้ในวอร์ดที่มีคนไม่มาก
จึงยังต้องดูแลเหมือนข้อมูลผู้ป่วยตามปกติ

### เรื่องความเป็นส่วนตัวของฟีเจอร์ “นำเข้าจากข้อความ”

ตัวอ่านข้อความดึงออกมาเฉพาะ **ค่าตัวเลขของ V/S และ Lab ที่รู้จักเท่านั้น**
ชื่อ-สกุล เลข HN และข้อความบรรยายอาการจะไม่ถูกดึงหรือบันทึกลงฐานข้อมูล
ถึงอย่างนั้น ข้อความต้นฉบับที่วางในช่องนำเข้าอาจมีข้อมูลระบุตัวตนอยู่
จึงควรวางเฉพาะส่วนที่เป็นค่าตรวจ และอย่าวางข้อความที่มีชื่อผู้ป่วยลงในเครื่องที่ไม่ปลอดภัย
